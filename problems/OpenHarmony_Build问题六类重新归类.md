# OpenHarmony Build 问题六类重新归类

## 1. 分类

| 类别                       | 定义                                                                       | 判断边界                                         |
| -------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------ |
| A1 工具环境准备            | 检查必需工具、命令、工具链组件和目标库是否存在、能否调用                   | “没有、未安装、未下载完整”归 A1                |
| A2 工具版本准确            | 检查工具或环境版本、实际身份、目标架构和行为是否正确                       | “存在，但版本、身份或目标不对”归 A2            |
| B 目标代码不完整           | 检查目标源码、构建脚本、子仓、设备代码和架构制品是否完整                   | 目标代码或脚本缺内容、缺步骤、缺仓库、缺制品归 B |
| C 文件目录环境准备、权限等 | 检查文件编码、命令传递、目录状态、所有者、权限和本地资源                   | 与源码内容无关的本地文件/目录/权限/资源问题归 C  |
| D 目标代码配置文件         | 检查产品、组件、overlay、内核、链接脚本和 GN/Ninja 构建配置                | 配置声明、参数或依赖关系错误归 D                 |
| E 外部网络                 | 检查外部端点、代理、DNS、HTTP 权限和限流                                   | 有明确网络、HTTP 或远端权限证据时归 E            |
| F 其他                     | 根因仍有多个候选、当前不是已确认故障、包含跨类别非阻塞信号，或属于结果判读 | 不能可靠落入 A1-E 时归 F，并说明保留原因         |

两处调整：

- `BUILD-031` 从 F 调整为 D。知识库已确认两个 Ninja 文件为同一个对象生成重复规则，直接根因属于构建图配置冲突；即使“为什么同时引入两套目标”仍待深入定位，也不影响主类别判断。
- `ENV-014` 从 A2 调整为 F。该记录同时包含 Node.js 版本偏低和 trace 目录不存在两个非阻塞警告，日志随后继续完成 ohpm 初始化并进入 LOAD/GN，不应把它写成单一版本故障。

### A1. 工具环境准备（10 条）
