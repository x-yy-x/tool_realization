# `src/precheck/` — 第 -2 / -1 层（两段预检）

**设计文档**：[`docs/02-流水线与关.md` §7](../../docs/02-流水线与关.md)（流水线）+ §26.6/§26.7（预检查什么）

**这两层不属四层里的任何一层**——它们是「**没有 L2 的四层**」：

| 层        | 预检里是什么                                    |
| --------- | ----------------------------------------------- |
| L1 扫描   | 探测环境（不扫源码树——**这时候还没有源码**） |
| L2 提取   | **没有。** 「提取」的定义是「从源码文件里读出声明」，预检没有源码 |
| L3 验证   | 拿探测结果对白名单 / 可达性清单                 |
| L4 判读   | 判读与处置                                      |

「两段预检没有 L2」是这套划分里唯一一处结构性空缺，不是遗漏。

## 这两层保护谁

| 层            | 跑在哪                  | 需要什么            | 保护谁                          |
| ------------- | ----------------------- | ------------------- | ------------------------------- |
| **第 -2 层** | **Windows 侧**    | 什么都不要          | 装 WSL / 装工具（分钟级）       |
| **第 -1 层** | WSL，**无源码树** | `repo` + manifest | `repo sync`（**小时级**） |

**顺序不能倒**：能查的必须查完，才允许做下一个昂贵动作。

## 本层文件的计划

| 文件            | 层       | 职责                                                       |
| --------------- | -------- | ---------------------------------------------------------- |
| `p_env.py`    | 第 -2 层 | WSL 分发源 / CDN / 代理 / apt 源 / Windows 侧 python 身份  |
| `p_fetch.py`  | 第 -1 层 | `repo` bootstrap + manifest 端点全量探测 + 并发风险预测 |
| `p_base.py`   | 第 -1 层 | 基线工具存在性 + 环境身份（OS / Python / Node vs 白名单）  |

**这三层是唯一已实现的部分**——原型在 `.claude/skills/edge-deploy/`（`probe.py` + `preflight.py`，实测通过），提上来时**把 `python` 改成 `py`**（Windows 上 `python` 会命中 Microsoft Store 存根）。

实现状态见根 [`README.md`](../../README.md) 的 STATUS 表。
