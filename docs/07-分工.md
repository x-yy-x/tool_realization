> **本文回答**：这一轮只做 **L1–L3**，四个人的活怎么切。
> **对应**：原设计文档 §29（四层）与 `src/` 的模块划分。
> **本文小节用 §31**——§29 是 [`02`](02-流水线与关.md) 的四层编号，§30 是 [`src/l4_triage_fix/`](../src/l4_triage_fix/README.md) 的，三处不能撞。

**本轮范围：L1–L3（扫描 → 提取 → 验证）。L4 判读与修改先不动。**

理由：L1–L3 全部只读、可离线自测；**L4 是唯一有副作用的层**（Agent 会改源码树），等前面三层跑通了再谈。

## 31.1 分层：三层，每层一句话

| 层                | 一句话                                       | 判据                                 |
| ----------------- | -------------------------------------------- | ------------------------------------ |
| **L1 扫描** | 把一棵源码树变成一份带分类的文件清单         | **只 `readdir`，不打开文件** |
| **L2 提取** | 从清单里那份文件里，读出它声明了哪些需求     | **只读源码，环境无关**         |
| **L3 验证** | 拿着需求清单，去目标环境里逐条问「满足了吗」 | **必须跑在被检查的机器上**     |

**L1–L3 全部只读**——不编译、不执行源码树里的任何脚本、不改任何东西。

---

## 31.2 输入输出

| 层           | 输入                                            | 输出                                                                  | 能离线自测吗             |
| ------------ | ----------------------------------------------- | --------------------------------------------------------------------- | ------------------------ |
| **L1** | 源码树根 +`config.yaml`（排除规则、哨兵路径） | `filelist.json` + 树模型（manifest 结果、bundle 索引）              | ✅ 用 fixture 假树       |
| **L2** | `filelist.json` + `rules/*.yaml`            | `requirements.json`（+ `extractor_stats` + `self_check`）       | ✅**完全离线**     |
| **L3** | `requirements.json` + 目标环境                | `findings.json`（每条带 `result` / `evidence` / `exit_code`） | ❌**必须进目标机** |

**契约就是 [`schema/`](../schema/README.md) 那三份 JSON。** 字段名对不上就是没接上。

## 31.3 每层具体完成什么任务

### L1：6 件事，一个文件 `treemodel.py`

| # | 任务                          | 做什么                                                                                                                                                     |
| - | ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 | `walk()` **遍历**     | `os.scandir` 递归走全树，**只记路径、不打开文件**。~184203 文件，秒级。**全场唯一一次全树遍历**                                              |
| 2 | **排除**                | `.git/` 全跳；`.repo/` 跳内容**留 manifest**；`out/` 跳内容**留路径**；`prebuilts/` 只建索引不解压。规则写在 `config.yaml`，原地剪枝 |
| 3 | `classify()` **分类** | 路径 + 文件名 → 12 种`kind`。纯函数，**只按后缀与路径，不读内容**（shebang 只读前 2 字节）                                                        |
| 4 | `parse_manifest()`          | 读**已合并的本地 manifest**（不是 `.repo/manifests/*.xml`，那份有 `<include>`）→ `name → {path, revision, remote}` + warnings                |
| 5 | `bundle_index()`            | 从 filelist 里挑出 bundle 类，建`name → path` 索引。**不重复走树**                                                                                |
| 6 | **固化**                | 写出`filelist.json`（`meta` + `files` + `stats`）。`stats.by_kind` 是第 2 关求差集的输入                                                         |

> **关键：遍历 ≠ 解析。** 遍历碰全部 ~184203，秒级；解析只碰认得的那 ~12930，分钟级。**L1 和 L2 的分界线就在这里。**

### L2：9 个模块，产出一份 `requirements.json`

**地基 1 个**

| 模块              | 做什么                                                                                                                 |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `shelltoken.py` | shell 分词器，S1 的地基。`tokenize` + `unwrap`（拆包装器：`sudo` / `timeout` 算需求，`env` / `time` 不算） |

**提取器 7 个**

| #  | 模块                | 从什么提取                                                           | 生成什么                                                                           |
| -- | ------------------- | -------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| S1 | `s1_tool.py`      | 脚本 / Makefile / GN`action` 里的命令                              | **宿主工具**需求。逐行取首词 → 滤黑名单 → 拆包装器 → 打分 high/medium/low |
| S2 | `s2_repo.py`      | `manifest.xml` + 源码里的 `//path` 引用                          | **源码仓**需求                                                               |
| S3 | `s3_part.py`      | 产品`config.json` + 各部件 `bundle.json` 的 `deps`             | **部件**需求，**迭代求传递闭包**，报缺失部件                           |
| S4 | `s4_toolchain.py` | 编译器名（`$CC`、`aarch64-linux-gnu-gcc`）+ `target_cpu`       | **工具链**需求 + 目标架构                                                    |
| S5 | `s5_lib.py`       | `BUILD.gn` 的 `-lfoo` / `libs` + `.ld` 的 `ENTRY()` 与符号 | **库与符号**需求                                                             |
| S6 | `s6_include.py`   | 使用 × 声明（用了`uint32_t` 却没有 `#include <cstdint>`）       | **头文件缺口**                                                               |
| S7 | `s7_config.py`    | `defconfig` 名 / GN `target_cpu`                                 | **配置与架构**需求                                                           |

**知识库 2 个**（没有声明来源的那一类）

| #  | 模块       | 做什么                                                                   |
| -- | ---------- | ------------------------------------------------------------------------ |
| K1 | 语义匹配   | `knowledge.yaml`——`mcopy` 缺 `-o` 这类**写法判读**         |
| K2 | 版本白名单 | `whitelist.yaml`——版本约束（Ubuntu / Python / Node）源码里根本没声明 |

**自检 1 个**

| 模块              | 做什么                                                                                                                                                       |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `v_coverage.py` | **第 2 关**：拿 `filelist.stats.by_kind` 和提取器的认领集**求差集**。没被认领的扩展名 → `warn`。**它是个回环**——补规则，重跑第 1 关 |

### L3：5 个验证器，产出 `findings.json`

| 模块                 | 验证原语 | 在第几关   | 做什么                                                                             |
| -------------------- | -------- | ---------- | ---------------------------------------------------------------------------------- |
| `v_tree.py`        | 不变量   | 第 0 关    | **树完整性**：哨兵路径 + 对账 manifest。前置且默认阻断                       |
| `v_exists.py`      | 存在性   | 第 3 关    | `command -v` / `test -f` / `test -d`                                         |
| `v_identity.py`    | 身份     | 第 4–5 关 | `-dumpmachine` / `readlink -f` / `-E -v`——**工具是不是它声称的那个** |
| `v_consistency.py` | 集合运算 | 第 5 关    | 纯集合求差，**静态，不需要目标环境**                                         |
| `v_reach.py`       | 可达性   | 第 6 关    | DNS → 连接 → 权限，三档，**每个请求带 `--max-time`**                     |

12 种 `kind` 多对一映射到验证器（如 `tool` / `repo` 都走存在性）。

## 31.4 四个人怎么分

| 人                 | 圈走哪些任务                                                                                                                                                                                | 为什么                                                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **总体把握** | **地基**（`config.yaml` 读取 / schema 落成 dataclass / `scan.py` 入口 / fixture 假树 / 测试框架）**+ 验收** + L3 的 `v_exists` / `v_identity` / `v_reach` / `probe` | 地基不写就等于四个人各写各的壳；L3 后三个**必须进目标机**，来回交接成本最高，自己拿着最省 |
| 甲                 | **L1 全部 6 件事** + `v_tree` + `v_consistency`，收尾接 `v_coverage`                                                                                                            | 建树模型的人和验树模型的人（`v_tree` 判哨兵/对账）**必须是同一个**，否则互相扯皮        |
| 乙                 | **L2 结构化那半**：`s2` 仓 + `s3` 部件 + `s4` 工具链 + `s7` 配置架构                                                                                                          | 读的是 XML / JSON，**确定性最高、fixture 能写死断言、最先出活**                           |
| 丙                 | **L2 文本那半**：`shelltoken` + `s1` 工具 + `s5` 库符号 + `s6` 头文件缺口                                                                                                     | **最难的一簇**——分词器 + 假阳性（R1）+ 使用×声明。给最强的人或最长的时间               |

**四条并行线，人在哪条上，看的是「他手里那几件事的输入从哪来」：**

| 线           | 人       | 输入从哪来                                             |
| ------------ | -------- | ------------------------------------------------------ |
| 环境线       | 总体把握 | 环境 +`config.yaml`，**跟源码树无关**          |
| 树线         | 甲       | **源码树**，产出 `filelist.json`               |
| 结构化声明线 | 乙       | `filelist.json`，产出 `requirements.json` 的一半   |
| 文本声明线   | 丙       | `filelist.json`，产出 `requirements.json` 的另一半 |

### 唯一的同步点是契约冻结

开工前必须先冻结三张表，否则乙丙产出的东西拼不成同一份 `requirements.json`：

| 冻结什么                           | 谁定 | 谁受影响                |
| ---------------------------------- | ---- | ----------------------- |
| `kind` 取值表（12 种）           | 甲   | 乙、丙                  |
| `check` 路由表（`CHK-*`）      | 全体 | 总体把握（L3 按它分派） |
| `declared_at` 一律 `路径:行号` | 全体 | 乙、丙                  |

冻结完，**四个人同时开工，谁也不用等谁**——因为每层吃文件吐文件：

- 乙、丙**手写一份 `filelist.json`** 就能开发，不用等甲
- 总体把握**手写一份 `requirements.json`** 就能开发 `v_exists`

**关键路径 L1→L2→L3 被文件解耦切断了。**

### 收口顺序

```
乙、丙各交 requirements.json 的一半
        ↓
     合并（同一个文件，按 id 段分配避免冲突）
        ↓
甲接 v_coverage 跑第 2 关  ← 它要消费全体产出，只能最后做
        ↓
总体把握接第 3–6 关
```
