# S1 按老师指导实现的分阶段处理流程

当前版本：0.3.0。处理链已经落实为实际调用关系：

```text
源码读取  scan_file()
    ↓ SourceDocument
分类解析  classify_source() → parse_source()
    ↓ ParsedSource
字面常量提取  extract_literals()
    ↓ LiteralBatch（常量、完整 argv、动态未解析项、脚本引用、诊断）
工具识别与过滤  recognize_tools()
    ↓ RecognizedBatch
来源与置信度标注  annotate_tool()
    ↓ requirements / references / unresolved / diagnostics
JSON 报告  scan() 汇总、排序、编号 → _write_report() 原子写入
```

## 代码分工与阶段边界

| 阶段 | 实现位置 | 输入与输出 | 边界 |
| --- | --- | --- | --- |
| 源码读取 | `extractors/s1_tool.py:ToolScanner.scan_file` | 文件路径 → `SourceDocument` | 根目录约束、去重、UTF-8/BOM 读取；只有协调层接触文件系统 |
| 分类解析 | `src/l2_extract/s1_parse.py` | `SourceDocument` → `ParsedSource` | 只生成各语言的语法结构与解析诊断；没有黑名单和最终需求对象 |
| 字面常量提取 | `src/l2_extract/s1_literals.py` | `ParsedSource` → `LiteralBatch` | 确定可静态读取的可执行词/参数；不求值变量、拼接、f-string 或任意 AST |
| 工具识别与过滤 | `src/l2_extract/s1_pipeline.py:recognize_tools` | `LiteralBatch` → `RecognizedBatch` | 处理内建/函数/人工黑名单、GN 裸词规则、工具与树内脚本引用的区别 |
| 来源与置信度标注 | `src/l2_extract/s1_pipeline.py:annotate_tool` | `RecognizedTool` → 需求字典 | 在这里生成 `declared_at`、`declared_as`、`confidence`、验证描述和问题映射；此前只保留来源上下文 |
| JSON 报告 | `extractors/s1_tool.py` | 需求与旁路证据 → JSON 文件 | 保留原有稳定排序、ID、去重、输入文件保护与原子替换行为 |

各阶段使用独立数据类型交接。解析器和常量提取器拿不到 `ToolScanner`；后两阶段拿不到 Python AST。`ToolScanner._process()` 依次调用这些函数，原先夹在语言解析中的需求构造逻辑已移出。

## 四类输入如何进入字面常量阶段

| 输入 | 分类解析得到什么 | 字面常量阶段提取什么 |
| --- | --- | --- |
| Shell | Token、命令段、函数定义范围；引号和嵌套边界由共享词法器保留 | 可执行位置的常量词与完整 argv；按包装器语法逐层定位载荷；普通字符串参数不会被重新当成命令 |
| Make | TAB 配方、逻辑续行、主目标、`.ONESHELL` 范围 | 先将 Make 变量保持为不透明表达式，再对配方走 Shell 解析与常量提取；保留 Make 原始配方证据 |
| GN | action/action_foreach 内的 script/args 赋值结构 | script 直接字符串作为引用；args 的直接字符串进入候选集；`rebase_path(...)`、动态 script 等保留未解析原因 |
| Python | AST 调用节点及对应的词法作用域/导入绑定 | 已确认进程相关调用中的字符串常量或 argv 首元素；动态参数保留标记，动态可执行名进入 unresolved |

对 `bash -c`、`python -c` 及 Python shell 字符串，静态载荷会再次经过“分类解析 → 常量提取”。GN 引用脚本由协调层读取，再走相同的完整链。两者都不执行源码。

## 看得见的阶段差异

例如 `build.sh` 中有：

```sh
echo "ninja"
timeout 500 hb build
"$TOOL" --version
```

1. 解析阶段形成三条命令的语法结构。
2. 字面常量阶段记录可执行词 `echo`、`timeout`、`hb`，保留每条完整参数；动态命令名 `$TOOL` 记录为 unresolved。字符串参数 `"ninja"` 不会被选成可执行词。
3. 识别阶段应用默认 Shell 内建规则，过滤 `echo`，得到 `timeout`、`hb`。
4. 标注阶段生成文件行号、原始命令片段，以及构建入口对应的 high 置信度。
5. 汇总阶段排序、去重并生成稳定 ID，最后写入 JSON。

常量阶段尚未决定哪些词是外部工具。对同一份 `LiteralBatch` 可以独立更换黑名单重新识别，无需重新读取或解析源码。

## 可重复检查

在仓库根目录运行：

```powershell
python tests/show_s1_stages.py
python -m unittest tests.test_s1_pipeline -v
python -m unittest discover -s tests -v
python tests/review_fp_fn.py
```

第一条读取当前四类样例、打印常量与识别结果的区别，并生成 `out/s1_pipeline_stages.json`。文件包含每个阶段的真实中间结果和最终扫描报告。

新增 12 项阶段边界测试。它们检查四类分类、各语言常量选择、动态表达式不求值、黑名单可独立更换、中间记录不可变、标注阶段才生成报告字段、CLI 的真实调用顺序、GN 递归重入相同处理链，以及解析/提取阶段不读文件或执行命令。

本版共 154 项测试通过。原始样例、四类扩展样例和 GN 单入口样例的需求、原文、引用、未解析项、诊断及统计与重构前逐项一致；版本号和扫描时间作为元数据单独更新。合成样例的误报/漏报核验仍为 PASS，其结果不代表真实 OpenHarmony 树准确率。

## 运行与接入边界

Python 3.10+，仅使用标准库。在仓库根目录运行：

```sh
python -m extractors.s1_tool --root tests/fixture_s1 --output out/s1_requirements.json --show-low
```

只给 GN 入口时，静态 script 引用仍会递归读取：

```sh
python -m extractors.s1_tool --root tests/fixture_s1 --path BUILD.gn --output out/s1_gn.json --show-low
```

程序接口：

```python
from extractors.s1_tool import scan_tree
from src.l2_extract.shelltoken import iter_commands

report = scan_tree(source_root, paths=["BUILD.gn"])
for command in iter_commands('$CC -o out "$OBJS" -lc -L "/sysroot/lib dir"'):
    print(command.argv)
```

旧 `lib.shelltoken` 导入通过兼容层调用同一实现。Make 原文应先经过配方和 Make 变量适配，不能整份直接交给 Shell 分词器。

本次提交只包含共享分词器、S1 及相关测试/样例。S5/S6 提取器、L1 的 filelist 消费接口、统一入口和 L3 验证仍待集成。当前 `scan_tree()` 按源码根目录或显式路径运行，输出是 **S1-only 独立报告**，尚未直接满足 `schema/requirements.schema.json` 的冻结契约：ID 为 `S1-*`，并保留 `references`、`unresolved`、`diagnostics`、`source_type` 等扩展证据。接入统一框架时需要映射全局 `REQ-*` ID、转换统计结构，并约定扩展证据的保存位置；不能将独立报告直接作为严格 schema 校验通过的全局产物。

现有包装器规则把外部 `env` 记录为工具依赖；直接外部执行中的 `echo` / `test` 等也保留为外部程序需求。这与 L2 设计示意中跳过 `env` 的规则存在差异，后续集成需统一口径。普通 Shell 内建仍在识别阶段过滤，自定义黑名单可人工抑制。

原始 fixture 的 `./build/genconfig.sh` 按树内引用处理；因为样例缺少该文件，会产生 `script_missing` 诊断，而不是凭文件名制造外部 `genconfig` 工具需求。新增 `fixture_s1/build.sh` 中的直接 `genconfig` 命令另行验证外部工具提取。
